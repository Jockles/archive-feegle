Chapter 2: The Core, Themes, and Extras

The Chat Container, and the anatomy of a Module.

The first step for every chat is to create a container for it:

<div class="mob imsg theme-auto">
</div>

This container has three classes, and each one has a job:

  • mob sets the phone-sized width and the base text styling. Every chat container except Discord has it.
  • imsg is the platform class. It decides which app the chat looks like. Here it makes an iMessage chat. It can only talk to the css in the iMessage module.
  • theme-auto is the theme class. It makes the chat light or dark to match the reader's device. Fixing a Chat to Light or Dark, further down this chapter, explains how to lock a chat to light or dark instead.

Platform Classes/Modules

To change which app the chat looks like, swap the platform class. Here is the full list:

  • imsg: iMessage
  • wa: WhatsApp
  • tw: a Twitter/X post, and tw-reply: a reply stacked under it
  • twdm: Twitter/X direct messages
  • ig: an Instagram post, and igdm: Instagram direct messages
  • tb: a Tumblr post
  • gm: a Gmail email, or a whole email thread
  • mail: a generic email window
  • dc: Discord

On a wide screen every chat except Discord is held to the width of a phone, and on a small screen it fills the width of the screen.

Phone Width or Full Width

Every chat is built to be the width of a phone, and I recommend leaving it that way. That's the size all of the designs are made for (except Discord, which is designed wide), so the layouts look their best at it. Anything that doesn't contain large images should scale wider just fine, but I've not optimised anything to work wide so you can use it at your own risk. This is mostly for anyone that wants full width texting-type chats for themselves. There is no desktop version of any of the apps in this, though I'd be open to adding them.

If you'd prefer a chat to fill the page, add the class wide to its container. It's available on every chat, and should resize cleanly to any page width:

<div class="mob imsg theme-auto wide">
</div>

The same class works on a tw-thread and a tb-feed. Here's the same chat both ways:

Jane: phone width

Ilya: the usual

Jane: full width

Ilya: stretches to fit the page

Discord goes the other way: it's wide to begin with, and you can add narrow to give it the width of a phone:

The discord container more easily resizes to be small on smaller screens, so the narrow skin is more for if you want it to look intentionally like a phone screen on desktop.

<div class="dc theme-auto narrow">
</div>

Each chat container's size is separate, so you can mix phone-width and full-width chats in one fic if that takes your fancy.

Cross-Platform Profiles

Profile Pictures

Most of the modules have round profile pictures next to people's names. There are three ways to fill one:

  1. Initials. Type them inside the circle, and add colour1 to colour10 for a colour.
  2. A picture. Put a picture tag, with alt text, inside a pfp span. Each module chapter shows you how.
  3. A profile. Set a character's picture once in the core CSS, and use it in every app. I'd recommend this for anyone who turns up in more than one chat.

iMessage, Twitter/X DMs and Instagram DMs don't show profile pictures.

Where the circle goes in each module
  • WhatsApp: wa-pfp, next to group messages and in the header.
  • Twitter/X: tw-pfp, at the start of the name line.
  • Instagram: ig-pfp beside the account name, and ig-like-pfp for the little faces in the "Liked by" line.
  • Tumblr: tb-pfp, at the start of the header.
  • Gmail: gm-pfp, beside the sender.
  • Discord: dc-pfp, first thing inside the dc-name. Without it, colour1 to colour10 give plain coloured circles, the same as in the other apps.

The colours for colour1 to colour10 are set in each module's CSS, so you can change them there.

Character Profiles

A profile is one character's online identity - their picture, name, handle and email address - set once in the core CSS. You can use it in any chat, in any app, and if something changes, like a new picture or a new handle, you change it in one place and it changes everywhere.

Here's Stan's. It's the simplest profile in this tutorial, and it's all most characters need:

/* PROFILE: Stan */
#workskin .pfp.pfp-stan { background-color: #c06a1f; }
#workskin .wa .who.pfp-stan, #workskin .dc .username.pfp-stan { color: #d2782a; }
#workskin .name.pfp-stan::before { content: "Stan"; }
#workskin .handle.pfp-stan::after { content: "PuckStan"; }
#workskin .email.pfp-stan::after { content: "Puckstan@gmail.com"; }

To make your own, copy Stan's block, change stan to your character's name everywhere in it, and fill in their details. Don't need a line? Delete it. For a picture instead of a coloured circle, swap the colour for background-image: url(LINK);, using a link that ends in .jpg or .png - AO3 is fussy about picture links in CSS.

The core CSS comes with all the profiles from this tutorial's examples - Stan, Yuna, Zim, Holster, Rose, Shane and Ilya - plus Luca, who uses every option there is, with a note on each line. Rename them, change them or delete them.

What each line of a profile does
  • Picture: the colour or picture in their circle.
  • Name colour: the colour of their name in WhatsApp groups and on Discord. Pick one that reads on both light and dark backgrounds.
  • Name: their name, in quotes.
  • Handle: their handle, in quotes, used on every app. Leave off the @ - Twitter/X adds it for you.
  • Email: their email address, in quotes, for Gmail and the email window.
Extras: a different picture, name or handle on one app, nicknames, and wallpapers

Most characters only need the five lines above. These are for characters who are different somewhere, and Luca's profile has an example of each one, so copy from there.

  • A different picture, name or handle on one app: add a line with the app in it. #workskin .tw .pfp.pfp-luca { background-image: url(LINK); } gives Luca a different picture on Twitter/X only, and #workskin .tw .name.pfp-luca::before { content: "Luca | cat dad"; } gives him a different name there.
  • Saved as: what the other characters have them saved as on their phones. #workskin .mob.pov-ilya .name.pfp-shane::before { content: "Jane"; } makes Shane show up as Jane on Ilya's phone. It goes in the profile of the person being named, so everything about how Shane shows up is in Shane's block.
  • Their phone: a wallpaper for WhatsApp chats on their phone - a colour, or a picture with background-image.
  • More than one account: give each one its own profile, like pfp-shane and pfp-shane-work.

Using a Profile

In your HTML, add the profile name wherever that character turns up:

  • Picture: <span class="pfp pfp-stan"></span>, inside any profile circle.
  • Name: <span class="name pfp-stan"></span>
  • Handle: <span class="handle pfp-stan"></span>
  • Email: <span class="email pfp-stan"></span>
  • Name colour: add pfp-stan to a WhatsApp who line or a Discord dc-name.

Names, handles and email addresses from a profile come from the CSS, so readers with the workskin switched off won't see them. That's why the examples have a hidden copy typed inside each one - there's more on that in Accessibility, below.

Good to know
  • A profile picture is cropped to fill the circle by itself, so wide pictures don't need land.
  • Names, handles and email addresses take on the look of the text around them, so they fit in anywhere.
  • The core CSS chapter explains how profiles work, line by line.

A profile can't pick a theme for you, so choose one for each character's phone and stick with it - Shane's is theme-light and Ilya's is theme-dark. With the wallpaper and the theme, readers can tell whose phone it is before they've read a word.

How saved names work
  • Saved names only show where you've used a name span. A name you've typed out stays as it is.
  • Anyone without a saved-as line for that phone shows up under the name in their profile, so you only need lines for the nicknames.
  • Make the wallpaper suit the theme: a pale one for a light phone, a dark one for a dark phone.

Accessibility (Click to expand)

This section explains every part of the workskin that's there for accessibility, but you don't need to add any of it yourself to get started - every example in this tutorial already has all of it built in, so if you copy them as they are, you're covered. It's here so you know what each bit does, and what to keep when you write your own.

A workskin only shows on AO3 itself. Anyone who switches off Creator's Style, or downloads your fic to read on an e-reader, sees your chats as plain text: no bubbles, no colours, and no way to tell which side a message was on. Screen readers can't see the pictures either.

The benefit of using a workskin instead of screenshots of an Instagram cloning tool or similar is that it makes it accessible for people who don't read AO3 on the site natively, so this is everything you need to know to make sure your beautiful socmed fic can be read by everyone. There are three tools for it:

  • hide, for text that's only there when the workskin is off. Anything in a hide span disappears when the workskin is on, and shows up as normal text when it's off.
  • Alt text, for pictures.
  • Video descriptions, for videos.

Who's Talking

In a one-to-one chat, no names are shown at all, so every message starts with the speaker's name in a hide span:

Jane: I heard you were working

Ilya: always working I do not rest

<p class="msg in"><span class="hide"><em>Jane:</em> </span>I heard you were working</p>
<p class="msg out"><span class="hide"><em>Ilya:</em> </span>always working I do not rest</p>

With the workskin off, readers get:

Jane: I heard you were working

Ilya: always working I do not rest

The speaker label, piece by piece
  • <p class="msg in"> and </p> - the bubble. With the workskin off, it's just an ordinary paragraph.
  • <span class="hide"> and </span> - only there for readers with the workskin off.
  • <em>Jane:</em> - the speaker's name, in italics, with a colon and a space. Keep the space before </span>, or the name runs straight into the message.
  • I heard you were working - the message itself, which everyone sees.

You only need speaker labels in chats made of bubbles: iMessage, WhatsApp, Twitter/X DMs and Instagram DMs. Tweets, posts, emails and Discord messages have the name written out already.

In a group chat, the name above someone's bubble (the who line) shows whether the workskin is on or off, so it only needs a hidden colon after it: <span class="hide">:</span>. Your own messages have no name above them, so they still need the full label.

Profiles

Names, handles and email addresses from a profile come from the CSS, so with the workskin off they're empty. Type a hidden copy inside the span:

<span class="handle pfp-stan"><span class="hide">PuckStan</span></span>

Readers with the workskin on see the profile's version, and readers with it off see what you typed. On Twitter/X, put the @ in your copy, because the workskin only adds it when it's on. It matters most where it's the only name on the screen: chat headers, WhatsApp who lines, Instagram and Tumblr posts, and Discord usernames.

Separators

Some bits of a chat sit apart on screen but come straight after each other in the code, like a name and the "online" underneath it. With the workskin off, they squish together into "Momonline". A hidden dash keeps them apart - <span class="hide"> - </span> - so it reads "Mom - online". Where a space reads better, like between a name and a ✓, use <span class="hide"> </span>.

Alt Text

Every picture needs alt text: a short description of what's in it. Screen readers read it out, and it shows in place of the picture if the picture doesn't load, whether the workskin is on or off. It goes on the picture tag itself, in alt. Describe the picture in a sentence or two, the way you'd describe it to someone over the phone:

Ilya: 

<p class="msg out pic"><span class="hide"><em>Ilya:</em> </span><img src="https://64.media.tumblr.com/a99a60f0293cf7df3604b4a6dd4705f6/ba033a52c8982cb0-cc/s1280x1920/cb4c277845d0c3ef666d16b86b75509266b795b3.jpg" alt="Black and white cat holding out a paw daintily, on a beige and green cat tree. The cat looks to be stepping into the frame from the left"></p>
More about alt text
  • You can't see alt text on the page, but you can check it's there. On a computer, right-click the picture and choose Inspect (or Inspect Accessibility Properties in Firefox), then look at the accessibility details for the picture - the alt text shows up as its name. Try it on the cat above.
  • The grey boxes with a description in square brackets (like [A photo of the rink]) are already text, so they don't need alt text.
  • Standard emojis don't need anything, because screen readers read them out and they stay as ordinary text with the workskin off. Only custom images, like ones you've uploaded and linked, need alt text.
  • A picture from a character's profile has no alt text, so screen readers skip it. That's fine next to a name, but if what's in the picture matters to your story, use a picture tag with alt text instead.
  • So: alt text for pictures, and hide for everything else.

Video Descriptions

AO3 doesn't give videos an alt text option, so the workskin has a class for it instead. Put a paragraph with vid-desc straight after the video, with a description of what happens in it in square brackets:

Jockles @jockles25 · 2h

Ilya Rozanov you will always be famous to me

[Video: a tribute edit of Ilya Rozanov, made from Heated Rivalry footage and set to "Would You Come Home" by Tyler Blackburn]

<div class="tw-media video"><iframe src="https://player.vimeo.com/video/1169167060?badge=0&amp;autopause=0&amp;player_id=0&amp;app_id=58479" frameborder="0" title="Ilya Rozanov | Come Home"></iframe><p class="vid-desc">[Video: a tribute edit of Ilya Rozanov, made from Heated Rivalry footage and set to "Would You Come Home" by Tyler Blackburn]</p></div>

Say who's in it, what happens, and the song if it's an edit. It works anywhere a video can go, and the WhatsApp and Twitter/X video examples already have one.

How video descriptions work

You can't see the description with the workskin on, but it isn't hidden the way hide is - it's moved off the edge of the screen instead, so screen readers still read it out. Anyone reading with the workskin switched off, or in a download, sees it as normal text under the video.

Everything that's only there for readers with the workskin off
  • Speaker labels at the start of a message: <span class="hide"><em>Jane:</em> </span>.
  • The colon after a group who name: <span class="hide">:</span>.
  • Separators: <span class="hide"> - </span> or <span class="hide"> </span>.
  • Hidden copies inside a profile's name, handle or email span.
  • "Replying to", a colon and square brackets around a quoted message in WhatsApp, so it reads "[Replying to Mom: Are you coming Sunday?]".
  • The brackets around a translation, so it reads "Diolch yn fawr (Thank you very much)".
  • Reactions, in square brackets: "[Jane reacted 😂]" in iMessage, and "[Reactions: ❤️ 😂 3]" in WhatsApp and Twitter/X DMs.
  • The # and the colon in a Discord channel header.
  • The words after the counts on Instagram's buttons, like "84 comments", and "likes (" and "when liked)" around the clickable heart's two counts.
  • Video descriptions (vid-desc), which screen readers read out too.

You can even hide whole sentences of narration this way, so a chat reads like a normal scene with the workskin off.

What works where

Everything in this chapter lives in the core CSS - the bit of the skin that every module needs - so you get all of it whichever modules you've picked. There are a couple of parts that don't work in Discord, but they're here because they work everywhere else.

Works in every module, Discord included

  • Character profiles (pfp-), and pov- for a character's phone
  • Accessibility: hide, alt text and video descriptions (vid-desc), for screen readers and for readers with the workskin switched off
  • Light, dark and auto themes
  • Pictures, and cropping them to fit boxes and circles (land)
  • Scrolling for long chats, and no-scroll to switch it off
  • Links that go nowhere (fake-link)
  • Width: phone width by default, and wide for full width (Discord is wide by default, and uses narrow for phone width instead)
  • Hover and tap translations, and hidden easter eggs (egg), which also work in ordinary text outside a chat

Works in every module except Discord

  • The typing line (typing)
  • Deleted or corrected text (del)

Light, dark and auto themes

Every chat in this tutorial uses theme-auto. It shows the chat in light colours, and switches to dark colours if the reader's phone or browser is set to dark mode. That way everyone gets the version that suits them, and you don't have to do anything extra.

FWIW: AO3 doesn't let a workskin see which AO3 site skin the reader is using, so theme-auto goes by the light or dark setting on their device or browser instead.

Fixing a Chat to Light or Dark

Sometimes you'll want a chat to look the same for everyone - a 3am text conversation on a phone that's always in dark mode, for example, or a chat that should always be light. To do that, swap theme-auto in the container for one of these:

  • theme-auto: follows the reader.
  • theme-light: always light, whatever the reader uses.
  • theme-dark: always dark, whatever the reader uses.

It's the same single word on the container for every module, Discord included.

Swapping the text when the reader hovers or taps, the brackets that show when Creator's Style is off, and using a link so that tapping works on a phone are all based on this. In this skin every translation is written in the HTML, so no new CSS is needed for each one.

If your characters switch languages every now and then, you can show the original words with the translation tucked away behind them. The reader sees the original with a dotted line under it, and when they hover over it on a computer, or tap it on a phone, the translation swaps in. It works in ordinary text as well as inside every chat and post in the skin, and the words take on the colour of whatever they're sitting in (dark mode included), so they never get mixed up with a chat link:

<a class="tl" href="#t1"><span class="orig">Diolch yn fawr</span><span class="tltn"><span class="hide"> (</span>Thank you very much<span class="hide">)</span></span></a>

The important bit is the opening tag: <a class="tl" href="#t1">.

  • tl is what makes the link a translation.
  • Every translation you make needs its own number in the href. Just count up after the t - #t1, #t2, #t3 and so on - and it'll work. Keep the numbers going across the whole fic rather than starting again each chapter, because readers can choose to see every chapter on one page.
  • The link is what makes the words tappable on a phone, and the # means the page doesn't jump anywhere when someone taps it.

What the rest does:

  • orig is the text the reader sees first.
  • tltn is the translation, shown on hover or tap.
  • The two hide spans add " (" and ")", but only when Creator's Style is off, so readers see "Diolch yn fawr (Thank you very much)" instead of the two run together.

Keep the whole thing on one line of code, like above, because a line break inside it can leave a gap in the middle of your sentence. Here it is in a sentence - hover over or tap the dotted words:

"Diolch yn fawr (Thank you very much)," he said.

The finished chat looks like this, and here is the full HTML:

<p>"<a class="tl" href="#t1"><span class="orig">Diolch yn fawr</span><span class="tltn"><span class="hide"> (</span>Thank you very much<span class="hide">)</span></span></a>," he said.</p>

In a chat, you just put it in the message text like any other words, with the next number along. This one is in an iMessage, and the next one is in a tweet:

Howell - iMessage

Howell: rough day?

Ilya: the worst

Howell: come here, you need a cwtch (hug)

The finished chat looks like this, and here is the full HTML:

<div class="mob imsg theme-auto">
  <p class="mob-head">Howell<span class="hide"> - </span><span>iMessage</span></p>
  <div class="mob-body">
    <p class="msg in"><span class="hide"><em>Howell:</em> </span>rough day?</p>
    <p class="msg out"><span class="hide"><em>Ilya:</em> </span>the worst</p>
    <p class="msg in"><span class="hide"><em>Howell:</em> </span>come here, you need a <a class="tl" href="#t2"><span class="orig">cwtch</span><span class="tltn"><span class="hide"> (</span>hug<span class="hide">)</span></span></a></p>
  </div>
</div>

Ilya Rozanov @irozanov · 7m

Bore da (Good morning)! I am learning Welsh now. Do not ask why.

The finished chat looks like this, and here is the full HTML:

<div class="mob tw theme-auto">
  <p class="tw-top"><span class="tw-name">Ilya Rozanov</span> <span class="tw-handle">@irozanov · 7m</span></p>
  <p class="tw-text"><a class="tl" href="#t3"><span class="orig">Bore da</span><span class="tltn"><span class="hide"> (</span>Good morning<span class="hide">)</span></span></a>! I am learning Welsh now. Do not ask why.</p>
</div>

A few things worth knowing:

  • A translation can have formatting inside it, like <em> for italics, because it's just ordinary HTML.
  • A chat bubble or box will grow or shrink a little to fit the translation when it swaps in. That's normal.
  • I'd recommend a line in your author's note telling readers they can hover over or tap the dotted words, so they know to try.

Hidden Text and Easter Eggs

A translation doesn't actually have to be a translation. The text that swaps in can be anything at all, so the same trick works for hidden text and easter eggs - a character's private thought, a joke, a hint about a later chapter, or a clue for anyone who goes looking. Put the visible words in orig and the surprise in tltn.

If you want it properly hidden, so nobody knows it's there until they stumble on it, add egg to the class: <a class="tl egg" href="#t4">. It works exactly like a translation (with its own number, the same as any other), but there's no dotted line, so the words take on everything about the text around them - the colour, bold, italics, the colour of a chat bubble - and look like ordinary text until someone hovers over or taps them. It works in every module. Hover over or tap the word "fine":

Scott - iMessage

Scott: how are you holding up?

Ilya: I'm fine (not fine. not even a little bit)

<p class="msg out"><span class="hide"><em>Ilya:</em> </span>I'm <a class="tl egg" href="#t4"><span class="orig">fine</span><span class="tltn"><span class="hide"> (</span>not fine. not even a little bit<span class="hide">)</span></span></a></p>

Readers with the workskin switched off still get the hidden text in brackets after the original, so nobody misses out completely. And if you'd like every translation in your fic to look like this, the core module's CSS chapter shows you the one line to delete instead.

These are the small touches that go inside a chat.

Pictures and Alt Text

Wherever a chat can show a picture (iMessage and DM pictures, tweet pictures, Instagram photos and profile pictures, Discord images), you add it with a normal picture tag. The picture has to be hosted somewhere else, and its link goes in src. Squidge.org is a great hosting platform that also lets you upload explicit images, and AO3 has a guide to some image hosting sites if you want more options.

AO3 Help - Embed Images

Every picture needs alt text too - a short description for screen readers, which goes in alt. It's all explained in Alt Text, in the Accessibility section above, along with Video Descriptions for videos. Every example with a picture already has its alt text, so you can just swap in your own link and description.

Pictures in Boxes and Circles

Some pictures are cropped to fit a box or a circle: the photo galleries in WhatsApp and Twitter/X, and profile pictures everywhere. AO3 can't crop pictures automatically, so the skin needs extra guidance if you're using a landscape picture:

  • A picture that is taller than wide, or square needs nothing. It's made as wide as the box, and the extra top and bottom is cropped away evenly. (In profile pictures the top of the photo is kept, so faces don't get cut off.)
  • A picture that is wider than tall needs class="land" on the picture tag. It's made as tall as the box, and the extra sides are cropped away evenly.

Scrolling Long Chats

Every chat, Discord included, stops growing at about the height of a phone screen. A short chat won't notice. A long one gets a slim scroll bar instead, so one long conversation doesn't take over the whole page.

  • iMessage, WhatsApp, Twitter/X DMs and Instagram DMs keep the header and the bottom bar where they are, and scroll the messages in between.
  • Twitter/X posts, Instagram posts, Tumblr posts and Gmail emails scroll as a whole.
  • Discord stays wide, and the whole window scrolls, header and message box included.

Links That Go Nowhere

Chats are full of links, but most of the time you don't want a real one - it could take the reader away from your fic, or point at a page that doesn't exist. For a link that looks clickable but doesn't go anywhere, put the address in a span with fake-link. It's coloured like a link in whichever app the chat is (and underlined too, apart from in Discord, which doesn't underline its links), so it works in every chat, Discord included:

Jane: have you seen hockeynews.example/overtime-goal

<p class="msg in"><span class="hide"><em>Jane:</em> </span>have you seen <span class="fake-link">hockeynews.example/overtime-goal</span></p>

Make up any address you like, since it's only text. A real link written with <a href="..."> inside a chat gets the same look, so use that if you do want it to go somewhere.

Works in every module except Discord

These two are for any chat built on the mob container, which is every module apart from Discord. Discord is its own kind of window, so these don't apply there.

Typing Line

To show that someone is typing, add a paragraph with typing at the end of the messages. It shows up as a small, slanted line of text:

Scott is typing...

<p class="typing">Scott is typing...</p>

Deleted or Corrected Text

To strike a message through, as if the sender deleted or corrected it, wrap the words in a span with the class del:

Ilya: I'm fine

<p class="msg out"><span class="hide"><em>Ilya:</em> </span><span class="del">I'm fine</span></p>

Putting It Together

Scott - @scotthunter

Ilya: I'm fine

Ilya: I'm not fine

Scott is typing...
