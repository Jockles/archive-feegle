This chapter goes through the CSS for the tweets, threads and DMs in the last chapter. The module has three parts: tweets and replies (tw and tw-reply), the scrolling thread they can sit in (tw-thread), and DMs (twdm). DMs are built just like iMessage, so if you've read that chapter, they'll be quick.

9.1 Getting the CSS

The Twitter/X CSS is here: jockles.com/fic/megaskin/css/twitter-x.css. It needs the core CSS too, so paste the core into your work skin first and this underneath it.

9.2 How the Module is Laid Out

The usual order - the main rules, Links, Dark theme and Auto theme - with a Scrolling section before the themes, because tweets and threads scroll differently from the phone-style chats, and Icons at the end. You'll notice that most rules name both .tw and .tw-reply. A reply is its own box rather than something inside a tweet, so every part that can turn up in both has to be given to both.

The timeline (tw-thread) is its own phone-sized box, built like the core's mob, and it holds every tweet in the chapter. The second rule takes the tweets inside it apart: no width of their own, no gap around them, no rounded corners, no scrolling, and only a bottom edge, so they stack into one feed with a line between each one. background: transparent and color: inherit make every tweet take the thread's colours, which is how a whole timeline follows one theme.

The top bar and tabs are just two flex rows at the top of the scrolling part of a timeline. In the top bar, the X gets flex: 1 to take up all the room left over, and its margin-right is the same width as the picture on the left, so the X sits in the true middle. The bird version hides the word inside by pushing it far off to the left with text-indent, and shows the logo picture in its place, the same way the icons work. In the tabs, the line under the picked tab is a ::after box filled with currentColor (the colour of the words), pinned to the bottom of the tab with position: absolute, stretched from left: 0 to right: 0 so it's always as wide as the words. The down arrow is just the bottom and right borders of a tiny square, turned 45 degrees with transform: rotate(45deg). The plus sign is pinned to the right-hand end the same way, with a background the same colour as the screen, so long tabs slide under it instead of pushing it off the edge.

The tw2020 rules all start with .tw-thread.tw2020, so they only touch a thread with both classes. The logo gets the same bird as bird, without the margin, because the sparkle now balances the picture: it's an ::after box on the top bar with the sparkle character as its content, the same width as the picture. In the stats row, the share button gets flex: 1 1 0 back so it spreads out like the others, and :not(:last-of-type) hides every tw-end button that isn't the last one in the row, which is the bookmark.

9.5 The Tweet

#workskin .tw {
  background: #ffffff;
  color: #0f1419;
  border: 1px solid #cfd9de;
  border-radius: 14px;
  padding: 0.8em 1em;
}

#workskin .tw-reply {
  background: #ffffff;
  color: #0f1419;
  border: 1px solid #cfd9de;
  border-top: none;
  padding: 0.7em 1em;
}

On its own, a tweet is a rounded card, white in light mode and black in dark mode. In a timeline, the timeline's rule above takes its edge and corners away. A reply is a square card with no top edge, so a stack of replies under a tweet joins up into one long card, with a single line between each one.

The text colours are Twitter/X's own: #0f1419 is its near-black, #536471 the grey for handles and small print, and #1d9bf0 its blue, which is used for links, hashtags, the verified tick and poll outlines.

#workskin .tw-reply .tw-name > .ic {

  margin: 0.15em 0 0 0.25em;
}

  flex: 0 100000 auto;
  background-size: 1em 1em;
  background-position: left center;
}

/* the handle shrinks a hundred thousand times faster than the name, so it has gone completely before the name starts to shrink */
#workskin .tw .tw-handle,
#workskin .tw-reply .tw-handle {
  flex: 0 100000 auto;
  min-width: 0;
  margin-left: 0.25em;
  overflow: hidden;
  text-overflow: ellipsis;
}

/* the time after the handle: <span class="tw-time">· 5m</span>. It never shrinks */
#workskin .tw .tw-time,
#workskin .tw-reply .tw-time {
  flex: none;
  margin-left: 0.25em;
  color: #536471;
}

/* a second grey line under the name, like "Fan account":
   <span class="tw-fan"><span class="ic ic-tw-fan">&#127917;</span> Fan account</span> at the end of tw-top. It sits under the name, beside the picture */
#workskin .tw .tw-fan,
#workskin .tw-reply .tw-fan {
  position: absolute;
  top: 1.3em;
  left: 40px;
  right: 0;
  margin-left: 0.55em;
  overflow: hidden;
  text-overflow: ellipsis;
  color: #536471;
}

#workskin .tw .tw-fan .ic,
#workskin .tw-reply .tw-fan .ic { margin-right: 0.2em; }

/* a tweet on its own, or the first tweet of a reply chain, is an opened tweet: its @handle and time go on a
   second line under the name, and a fan account line goes under them. In a feed (a tw-thread with app)
   and in replies, they stay on one line */
#workskin .tw .tw-top {
  display: block;
  text-overflow: ellipsis;
}

#workskin .tw .tw-pfp { float: left; }

#workskin .tw .tw-handle,
#workskin .tw .tw-time { margin-left: 0; }

#workskin .tw .tw-fan { display: block; position: static; margin-left: 0; }

#workskin .tw-thread.app .tw .tw-top { display: flex; }

#workskin .tw-thread.app .tw .tw-handle,
#workskin .tw-thread.app .tw .tw-time { margin-left: 0.25em; }

#workskin .tw-thread.app .tw .tw-fan { position: absolute; margin-left: 0.55em; }
  • The name line is a flex row, with the picture, name, handle, padlock and time side by side. white-space: nowrap keeps them all on one line, however long they are, and overflow: hidden cuts off anything that still doesn't fit.
  • When the row is too long, flex shrinks the boxes in it. flex-shrink (the middle number in flex: 0 100000 auto) says how fast each one shrinks: the handle's is 100000 and the name's is 1, so the handle shrinks a hundred thousand times faster. That's so fast that it's gone completely before the name has shrunk by even a fraction of a pixel, so you never see a cut-off name next to a scrap of handle. min-width: 0 is what allows a box to shrink smaller than its words. The time and the padlock get flex: none, so they never shrink at all.
  • text-overflow: ellipsis puts "..." where the handle or the name is cut. The name is a flex row too, so its tick can shrink away before the name does. The tick's background-size is fixed, so it gets cut off instead of squashed.
  • A name typed straight in, with no span around it, can't get the "...", so it wraps onto a hidden second line instead: max-height: 1.3em, the same as the line-height, shows the first line and hides the rest.
  • The picture is 40px tall, which leaves room under the name for a second line. tw-fan is pinned there with position: absolute, starting just past the picture, so it doesn't push the tweet down.
  • The last few rules are for an opened tweet: a tw on its own, or the first tweet of a reply chain. There, the name line goes back to display: block, the picture floats to the left, the name (still a flex box) takes the first line, and the handle and time flow onto the line under it. The fan line goes back to being an ordinary block, under the handle. The rules starting .tw-thread.app switch the one-line layout back on for tweets in a feed.
  • Initials circles take colour1 to colour10, the same ten colours as every other app, which are in the core.

Most of the parts of a tweet are simple: a line with its own size, colour and spacing. The row of buttons is a flex row, like the bottom of a Tumblr post. flex: 1 1 0 gives each button an equal share of the width, so replies, reposts, likes and views spread out evenly. tw-end switches that off with flex: none, so the bookmark and share buttons only take up as much room as they need, and sit together at the right-hand end. The main tweet's row has a pale line above it, and a reply's row is smaller with no line. The buttons themselves are pictures, in the Icons section at the end of the module. A quote tweet is a smaller rounded box inside the tweet. The Community Note (tw-note) and the sensitive content cover (tw-warn) are boxes the same way, with a pale grey background.

The clickable like and bookmark work the same way as Instagram's heart: the summary holds a count marked off and one marked on, and [open] means "after it's been clicked", which hides the first and shows the second. The little arrow that details normally shows is switched off with list-style and the two marker rules.

A button the account has used turns red for a like, green for a repost or blue for a bookmark, count and all, and a clicked like turns red the same way. A clicked bookmark turns blue: .tw-tog.tw-end picks out the bookmark, and is more specific than the red rule, so it wins. tw-locked fades a private tweet's repost button to pale grey, or dark grey in dark mode. The coloured pictures are in the Icons section too.

An open poll is a blue outline with very round corners and bold blue words in the middle. The results (res) turns the option into a flex row, like the buttons along the bottom of a tweet: the tw-bar span with the option in it, then the percentage pushed to the far right by margin-left: auto. The bar is a grey box with slightly rounded corners, and each p class sets how wide it is. min-width keeps a tiny percentage from shrinking the bar to nothing, and nowrap lets the words run on past the end of a short bar, like the real thing. win swaps the grey bar for a blue one and makes the text bold.

#workskin .tw .tw-opt.p75 .tw-bar, #workskin .tw-reply .tw-opt.p75 .tw-bar { width: 75%; }
#workskin .tw .tw-opt.p80 .tw-bar, #workskin .tw-reply .tw-opt.p80 .tw-bar { width: 80%; }
#workskin .tw .tw-opt.p90 .tw-bar, #workskin .tw-reply .tw-opt.p90 .tw-bar { width: 90%; }
#workskin .tw .tw-opt.p100 .tw-bar, #workskin .tw-reply .tw-opt.p100 .tw-bar { width: 100%; }

The percentage the reader sees is just the text in tw-pct, so any number can go there. The bar only comes in these sizes, though, and the nearest one is usually close enough. If you want a bar of an exact length, copy one of the rules into your skin, change the three numbers, and give the option that class. For a 58% bar:

#workskin .tw .tw-opt.p58 .tw-bar, #workskin .tw-reply .tw-opt.p58 .tw-bar { width: 58%; }

Then <p class="tw-opt res p58">lt;span class="tw-opt res p58"<p class="tw-opt res p58">gt; gets a bar 58% of the way across. The class name can be anything, but keeping the number in it makes it easy to remember.

/* the tick in a circle on the option the account voted for */
#workskin .tw .tw-voted,
#workskin .tw-reply .tw-voted {

  height: 1.1em;

  font-weight: bold;

}

/* TAPPABLE POLL, the short way: <details class="tw-vote"> with the open poll in <summary> (spans with tw-opt,
   and a tw-pollinfo span), then the results after it, with tw-voted on the pov character's vote.
   Tapping shows the results instead. */
#workskin .tw .tw-vote,
#workskin .tw-reply .tw-vote,
#workskin .tw .tw-vote > summary,
#workskin .tw-reply .tw-vote > summary { display: block; }

#workskin .tw .tw-vote > summary,
#workskin .tw-reply .tw-vote > summary,
#workskin .tw .tw-pick > summary,
#workskin .tw-reply .tw-pick > summary { cursor: pointer; list-style: none; }

#workskin .tw .tw-vote > summary::-webkit-details-marker,
#workskin .tw-reply .tw-vote > summary::-webkit-details-marker,
#workskin .tw .tw-pick > summary::-webkit-details-marker,
#workskin .tw-reply .tw-pick > summary::-webkit-details-marker { display: none; }

#workskin .tw .tw-vote > summary::marker,
#workskin .tw-reply .tw-vote > summary::marker,
#workskin .tw .tw-pick > summary::marker,
#workskin .tw-reply .tw-pick > summary::marker { content: ""; }

#workskin .tw .tw-vote[open] > summary,
#workskin .tw-reply .tw-vote[open] > summary { display: none; }

/* TAPPABLE POLL where the reader picks: <div class="tw-poll">, then one <details class="tw-pick"> per option,
   each with <summary class="tw-opt">Option</summary> and a <div class="tw-results"> holding the results
   with tw-voted on that option. The results cover the poll when it's tapped. */
#workskin .tw .tw-poll,
#workskin .tw-reply .tw-poll { display: block; position: relative; }

#workskin .tw .tw-pick,
#workskin .tw-reply .tw-pick { display: block; margin: 0.35em 0; }

#workskin .tw .tw-pick > .tw-opt,
#workskin .tw-reply .tw-pick > .tw-opt { margin: 0; }

#workskin .tw .tw-pick[open] > summary,
#workskin .tw-reply .tw-pick[open] > summary { visibility: hidden; }

#workskin .tw .tw-results,
#workskin .tw-reply .tw-results { display: block; position: absolute; top: -0.35em; left: 0; right: 0; z-index: 1; background: #ffffff; }

The tick is just a tick character in a span with a thin round border: border-radius: 50% turns a square into a circle. With no colour given, the border takes the colour of the words.

The tappable polls work exactly like Tumblr's. In tw-vote, the open poll is the summary, and [open] hides it once it's been tapped, so the results underneath show instead. In the reader-picks version, each option is its own details, and its tw-results box is lifted out of the line with position: absolute so it sits over the whole tw-poll box, starting at the top. The white background (black in dark mode) hides the options underneath, and z-index keeps it on top. The tapped option's own outline is hidden with visibility: hidden, which keeps its space so nothing jumps about.

9.10 Pictures and Videos

#workskin .tw .tw-media,
#workskin .tw-reply .tw-media {
  display: block;
  overflow: hidden;
  border: 1px solid #cfd9de;
  border-radius: 14px;
  margin: 0.5em 0;
  background: #eff3f4;
  color: #536471;
  font-style: italic;
  text-align: center;
  line-height: 1.3;
}

One picture fills the rounded box at its own shape, and overflow: hidden rounds off its corners with the box. An embedded video (video) is 200px tall, and a description gets padding to make it about the size of a picture.

Two, three and four pictures work exactly like WhatsApp's photo galleries - squares made with padding-top, floated into a grid, with land for wide pictures - so see Photo Galleries for how. The only differences are the sizes (49.2% squares with a 1.2% gap, adding up to 99.6%), and this at the end:

#workskin .tw .tw-media.two::after,
#workskin .tw .tw-media.three::after,
#workskin .tw .tw-media.four::after {
  content: "";
  display: block;
  clear: both;
}

Floating things don't take up any height, so a box of floated pictures would shrink to nothing, and the stats line would slide up behind the pictures. This adds an invisible empty line after them with clear: both, which means "go below anything floating", so the box stretches down to hold them.

9.11 Scrolling

#workskin .tw-thread .tw-scroll {
  display: block;
  max-height: 580px;
  overflow-y: auto;
  overflow-x: hidden;
}

#workskin .tw-thread.no-scroll .tw-scroll { max-height: none; overflow-y: visible; }

#workskin .tw {
  max-height: 700px;
  overflow-y: auto;
  overflow-x: hidden;
}

In a thread, only the tw-scroll part scrolls, at the same height as every other chat. A tweet on its own scrolls as a whole, and it's allowed to be taller (700px), because a tweet with a picture is usually taller than a chat window and you'd rather not scroll it if you can help it. Adding no-scroll to a tweet switches its scrolling off, as usual, and adding it to the tw-thread switches off the scrolling inside it.

9.14 Dark and Auto Themes

#workskin .tw.theme-dark { background: #000000; color: #e7e9ea; border-color: #2f3336; }

#workskin .tw-thread.theme-dark { background: #000000; color: #e7e9ea; border-color: #2f3336; }

#workskin .tw-thread.theme-dark .tw-replying,
#workskin .tw-thread.theme-dark .tw-date,
#workskin .tw-thread.theme-dark .tw-label,
#workskin .tw-thread.theme-dark .tw-pollinfo {
  color: #71767b;
}

Twitter/X's dark mode is black, with #e7e9ea for text and #71767b for grey. Tweets, replies and DMs each have their own dark rules, as you'd expect. Threads have a second set: every part of a tweet again, but starting .tw-thread.theme-dark. That's what lets you put theme-dark on the thread once instead of on every tweet inside it - the tweets don't have a theme of their own, so they need to be told by the thread.

The auto theme is the whole lot again inside @media (prefers-color-scheme: dark), so change a dark colour in both places.

9.15 Taking Parts Out

Search for the class names and delete every rule with them in, including in the dark and auto blocks:

  • DMs: everything starting .twdm, and anything with twdm- in it.
  • Threads: everything starting .tw-thread, and tw-scroll and tw-foot.
  • Polls: tw-opt, tw-pct and tw-pollinfo, which is also the biggest saving, since there are 15 bar sizes.
  • Picture galleries: tw-photo and tw-desc, and the two, three and four rules. Keep tw-media for single pictures.
  • Extras: tw-note, tw-warn, tw-label, tw-liked and tw-rt each come out on their own.

Keep the tweet, name line, text and stats, and tw-reply if you use replies anywhere.
