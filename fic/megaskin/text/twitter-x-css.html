Thanks to worlds_end_valentine, whose Twitter Work Skin Template this module is built on. Copied and adapted from it: the timestamp line, liked and reposted counts, labels, the sensitive content warning, polls, pictures and videos, scrollable threads, and DM reactions, group DMs, voice messages and the DM window.

This chapter goes through the CSS for the tweets, threads and DMs in the last chapter. The module has three parts: tweets and replies (tw and tw-reply), the scrolling thread they can sit in (tw-thread), and DMs (twdm). DMs are built just like iMessage, so if you've read that chapter, they'll be quick.

Getting the CSS

The Twitter/X CSS is here: jockles.com/fic/megaskin/css/twitter-x.css. It needs the core CSS too, so paste the core into your work skin first and this underneath it.

How the Module is Laid Out

The usual order - the main rules, Links, Dark theme and Auto theme - with a Scrolling section before the themes, because tweets and threads scroll differently from the phone-style chats, and Icons at the end. You'll notice that most rules name both .tw and .tw-reply. A reply is its own box rather than something inside a tweet, so every part that can turn up in both has to be given to both.

The Tweet

#workskin .tw {
  background: #ffffff;
  color: #0f1419;
  border: 1px solid #cfd9de;
  border-radius: 14px;
  padding: 0.8em 1em;
}

#workskin .tw-reply {
  background: #ffffff;
  color: #0f1419;
  border: 1px solid #cfd9de;
  border-top: none;
  padding: 0.7em 1em;
}

A tweet is a rounded white card. A reply is a square one with no top edge, so a stack of replies under a tweet joins up into one long card, with a single line between each one.

The text colours are Twitter/X's own: #0f1419 is its near-black, #536471 the grey for handles and small print, and #1d9bf0 its blue, which is used for links, hashtags, the verified tick and poll outlines.

  border-radius: 50%;
  overflow: hidden;
  text-align: center;
  background-color: #8b98a5;
  color: #ffffff;
  font-size: 0.85em;
  font-weight: bold;
}

#workskin .tw .tw-pfp ~ .tw-handle,
#workskin .tw-reply .tw-pfp ~ .tw-handle { display: block; }
  • The picture floats to the left, and the name and handle sit beside it.
  • overflow: hidden on the name line makes it grow tall enough to hold the floating picture. Without it, the tweet text would start beside the picture instead of under it.
  • ~ means "anywhere after, in the same line". So the last rule says: if there's a picture in the name line, put the handle on its own line under the name, the way Twitter/X does. With no picture, the handle stays beside the name.
  • Initials circles take colour1 to colour10, the same ten colours as every other app, which are in the core.

Most of the parts of a tweet are simple: a line with its own size, colour and spacing. The row of buttons is a flex row, like the bottom of a Tumblr post. flex: 1 1 0 gives each button an equal share of the width, so replies, reposts, likes and views spread out evenly. tw-end switches that off with flex: none, so the bookmark and share buttons only take up as much room as they need, and sit together at the right-hand end. The main tweet's row has a pale line above it, and a reply's row is smaller with no line. The buttons themselves are pictures, in the Icons section at the end of the module. A quote tweet is a smaller rounded box inside the tweet. The Community Note (tw-note) and the sensitive content cover (tw-warn) are boxes the same way, with a pale grey background.

The clickable like works the same way as Instagram's heart: the summary holds a count marked off and one marked on, and [open] means "after it's been clicked", which hides the first and shows the second. The little arrow that details normally shows is switched off with list-style and the two marker rules.

A button the account has used turns red for a like, green for a repost or blue for a bookmark, count and all, and a clicked like turns red the same way. tw-locked fades a private tweet's repost button to pale grey, or dark grey in dark mode. The coloured pictures are in the Icons section too.

An open poll is a blue outline with very round corners and bold blue words in the middle. The results (res) turns the option into a flex row, like the buttons along the bottom of a tweet: the tw-bar span with the option in it, then the percentage pushed to the far right by margin-left: auto. The bar is a grey box with slightly rounded corners, and each p class sets how wide it is. min-width keeps a tiny percentage from shrinking the bar to nothing, and nowrap lets the words run on past the end of a short bar, like the real thing. win swaps the grey bar for a blue one and makes the text bold.

Adding a poll percentage that isn't there

The skin has p0 to p100 in tens, plus p25, p33, p67 and p75. To add another, copy one of the rules and change all three numbers:

#workskin .tw .tw-opt.p45 .tw-bar, #workskin .tw-reply .tw-opt.p45 .tw-bar { width: 45%; }

The percentage the reader sees is just the text in tw-pct, so it doesn't have to match the bar exactly - the nearest bar is usually close enough.

The tick is just a tick character in a span with a thin round border: border-radius: 50% turns a square into a circle. With no colour given, the border takes the colour of the words.

The tappable polls work exactly like Tumblr's. In tw-vote, the open poll is the summary, and [open] hides it once it's been tapped, so the results underneath show instead. In the reader-picks version, each option is its own details, and its tw-results box is lifted out of the line with position: absolute so it sits over the whole tw-poll box, starting at the top. The white background (black in dark mode) hides the options underneath, and z-index keeps it on top. The tapped option's own outline is hidden with visibility: hidden, which keeps its space so nothing jumps about.

Pictures and Videos

#workskin .tw .tw-media,
#workskin .tw-reply .tw-media {
  display: block;
  overflow: hidden;
  border: 1px solid #cfd9de;
  border-radius: 14px;
  margin: 0.5em 0;
  background: #eff3f4;
  color: #536471;
  font-style: italic;
  text-align: center;
  line-height: 1.3;
}

One picture fills the rounded box at its own shape, and overflow: hidden rounds off its corners with the box. An embedded video (video) is 200px tall, and a description gets padding to make it about the size of a picture.

Two, three and four pictures work exactly like WhatsApp's photo galleries - squares made with padding-top, floated into a grid, with land for wide pictures - so see Photo Galleries for how. The only differences are the sizes (49.2% squares with a 1.2% gap, adding up to 99.6%), and this at the end:

#workskin .tw .tw-media.two::after,
#workskin .tw .tw-media.three::after,
#workskin .tw .tw-media.four::after {
  content: "";
  display: block;
  clear: both;
}

Floating things don't take up any height, so a box of floated pictures would shrink to nothing, and the stats line would slide up behind the pictures. This adds an invisible empty line after them with clear: both, which means "go below anything floating", so the box stretches down to hold them.

The app screen is just two flex rows at the top of the scrolling part of a thread. In the top bar, the X gets flex: 1 to take up all the room left over, and its margin-right is the same width as the picture on the left, so the X sits in the true middle. The bird version hides the word inside by pushing it far off to the left with text-indent, and shows the logo picture in its place, the same way the icons work. In the tabs, the line under the picked tab is a ::after box filled with currentColor (the colour of the words), pinned to the bottom of the tab with position: absolute, stretched from left: 0 to right: 0 so it's always as wide as the words. The down arrow is just the bottom and right borders of a tiny square, turned 45 degrees with transform: rotate(45deg). The plus sign is pinned to the right-hand end the same way, with a background the same colour as the screen, so long tabs slide under it instead of pushing it off the edge.

The tw2022 rules all start with .tw-thread.tw2022, so they only touch a thread with both classes. The logo gets the same bird as bird, without the margin, because the sparkle now balances the picture: it's an ::after box on the top bar with the sparkle character as its content, the same width as the picture. In the stats row, the share button gets flex: 1 1 0 back so it spreads out like the others, and :not(:last-of-type) hides every tw-end button that isn't the last one in the row, which is the bookmark.

  max-height: 700px;

In a thread, only the tw-scroll part scrolls, at the same height as every other chat. A tweet on its own scrolls as a whole, and it's allowed to be taller (700px), because a tweet with a picture is usually taller than a chat window and you'd rather not scroll it if you can help it. Adding no-scroll to a tweet switches its scrolling off, as usual.

Blue everywhere, except in your own blue DM bubbles, where links are white so they show up. tw-link, for hashtags and @mentions, is the same blue.

Dark and Auto Themes

#workskin .tw.theme-dark { background: #000000; color: #e7e9ea; border-color: #2f3336; }

#workskin .tw-thread.theme-dark { background: #000000; color: #e7e9ea; border-color: #2f3336; }

#workskin .tw-thread.theme-dark .tw-replying,
#workskin .tw-thread.theme-dark .tw-date,
#workskin .tw-thread.theme-dark .tw-label,
#workskin .tw-thread.theme-dark .tw-pollinfo {
  color: #71767b;
}

Twitter/X's dark mode is black, with #e7e9ea for text and #71767b for grey. Tweets, replies and DMs each have their own dark rules, as you'd expect. Threads have a second set: every part of a tweet again, but starting .tw-thread.theme-dark. That's what lets you put theme-dark on the thread once instead of on every tweet inside it - the tweets don't have a theme of their own, so they need to be told by the thread.

The auto theme is the whole lot again inside @media (prefers-color-scheme: dark), so change a dark colour in both places.

Taking Parts Out

Search for the class names and delete every rule with them in, including in the dark and auto blocks:

  • DMs: everything starting .twdm, and anything with twdm- in it.
  • Threads: everything starting .tw-thread, and tw-scroll and tw-foot.
  • Polls: tw-opt, tw-pct and tw-pollinfo, which is also the biggest saving, since there are 15 bar sizes.
  • Picture galleries: tw-photo and tw-desc, and the two, three and four rules. Keep tw-media for single pictures.
  • Extras: tw-note, tw-warn, tw-label, tw-liked and tw-rt each come out on their own.

Keep the tweet, name line, text and stats, and tw-reply if you use replies anywhere.
